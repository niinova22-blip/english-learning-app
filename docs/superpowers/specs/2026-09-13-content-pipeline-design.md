# Content Generation Pipeline — Design Spec

Date: 2026-09-13
Status: Approved for implementation planning
Slice: 3 of N (follows learning-engine and app-shell; see the
learning-engine spec's future-slices list)

## Context

Slices 1-2 built a real engine and a real app shell, but the only
content in the app is `SampleContent`'s 18 hand-written items — a test
fixture, not real learning material. This slice replaces that with a
real content-authoring pipeline: a data-driven JSON format, a
`ContentImporter` that loads it into the existing SwiftData model, and
an actual first batch of high-quality content generated against a
real, research-grounded word list rather than invented from memory.

## Content source (grounding, not invention)

Words for this first batch come from the **Academic Word List (AWL)**
— Averil Coxhead's 570-word-family list of vocabulary that appears
disproportionately often in academic texts, standard in ELT/EAP
research and freely usable. It's a strong match for YDS specifically,
since YDS tests academic-register English reading comprehension. This
slice uses **AWL Sublist 1 and Sublist 2** (the 120 most frequent
academic word families, verified against eapfoundation.com's published
AWL sublists on 2026-09-13):

**Sublist 1 (60):** analyse, approach, area, assess, assume,
authority, available, benefit, concept, consist, constitute, context,
contract, create, data, define, derive, distribute, economy,
environment, establish, estimate, evident, export, factor, finance,
formula, function, identify, income, indicate, individual, interpret,
involve, issue, labour, legal, legislate, major, method, occur,
percent, period, policy, principle, proceed, process, require,
research, respond, role, section, sector, significant, similar,
source, specific, structure, theory, vary

**Sublist 2 (60):** achieve, acquire, administrate, affect,
appropriate, aspect, assist, category, chapter, commission, community,
complex, compute, conclude, conduct, consequent, construct, consume,
credit, culture, design, distinct, element, equate, evaluate, feature,
final, focus, impact, injure, institute, invest, item, journal,
maintain, normal, obtain, participate, perceive, positive, potential,
previous, primary, purchase, range, region, regulate, relevant,
reside, resource, restrict, secure, seek, select, site, strategy,
survey, text, tradition, transfer

Future content batches can draw on AWL Sublists 3-10, or a
general-frequency list (e.g. NGSL) for non-academic packages
(Conversational, Business) — this slice only needs to establish the
pipeline and produce the first real batch.

## Goals

- A JSON content-authoring format that maps directly onto
  `LearningEngine`'s existing SwiftData model (`ContentPackage` →
  `Unit` → `Lesson` → `LearningItem` → `ItemContent`) — no schema
  changes to `LearningEngine` itself.
- `ContentImporter` (in `LearningEngine`, unit-tested against a small
  fixture): decodes that JSON and builds the same object graph
  `SampleContent` builds by hand.
- A real first content package — a "YDS: Academic Vocabulary I" bundle
  covering all 120 AWL Sublist-1/2 words, organized into thematically
  coherent units/lessons, each word carrying a genuine definition,
  2-3 example sentences, a Turkish translation, and collocations where
  natural — generated by Claude subagents in this session, not
  invented ad hoc by a single pass.
- The app (`App/`) bundles the generated JSON as a resource and seeds
  from it via `ContentImporter` instead of `SampleContent`.

## Non-goals

- No changes to `LearningEngine`'s SwiftData schema or FSRS/scheduling
  logic — this slice is purely upstream of it (feeding real data in).
- No UI changes beyond what's needed to display richer content (if
  any field the UI doesn't already render turns out to be needed,
  that's a call to make at plan time — see plan for the resolution).
- No other packages (TOEFL, Business, Conversational) in this slice —
  YDS only, to keep scope bounded; the pipeline itself is reusable for
  those later.
- No third-party translation API — Turkish translations are written by
  the same generation pass as the rest of the content (a competent
  bilingual pass), not machine-translated separately.
- `SampleContent` is untouched — it remains `LearningEngine`'s internal
  test fixture, used by `LearningEngine`'s own test suite. This slice
  adds a separate, real content package alongside it, it does not
  replace it inside the package.

## Content JSON format

One `ContentPackageDocument` per package:

```json
{
  "id": "yds-academic-vocab-1",
  "name": "YDS: Academic Vocabulary I",
  "goal": "yds",
  "levelLower": "B2",
  "levelUpper": "C1",
  "units": [
    {
      "id": "yds-vocab1-unit-business-economics",
      "theme": "Business & Economics",
      "order": 0,
      "lessons": [
        {
          "id": "yds-vocab1-lesson-1",
          "order": 0,
          "estimatedDurationMinutes": 5,
          "items": [
            {
              "id": "yds-vocab1-item-economy",
              "type": "vocabulary",
              "headword": "economy",
              "frequencyRank": 1200,
              "baseDifficulty": 0.3,
              "definition": "the system of production, trade, and management of money in a country or region",
              "exampleSentences": [
                "The country's economy grew by three percent last year.",
                "Rising fuel prices have hurt the local economy."
              ],
              "translationTR": "ekonomi",
              "collocations": ["global economy", "the economy grows", "economy of scale"]
            }
          ]
        }
      ]
    }
  ]
}
```

`type` is one of `vocabulary` / `grammarPoint` / `phrase` /
`collocation` (matching `LearningItemType`). `goal` is one of
`yds`/`toefl`/`business`/`conversational`/`custom` (matching
`LearningGoal`). `frequencyRank` is a relative ordering within this
batch (lower = more frequent/foundational) — not a claim about the
word's rank in the whole English language, just enough for
`LearningItem.frequencyRank` to be meaningful for future
prioritization logic. `id` values follow the existing convention seen
in `SampleContent` (a stable, human-readable slug) so imported content
merges predictably if a package is re-imported.

Every field is required (no optional fields in v1) — a partial/missing
field fails the import rather than silently producing a half-formed
`LearningItem`, since bad content silently reaching the app is worse
than a loud import failure during content authoring.

## ContentImporter

`LearningEngine` gets a new `Import/` group:

- `ContentPackageDocument`, `UnitDocument`, `LessonDocument`,
  `LearningItemDocument` — plain `Decodable` structs mirroring the
  JSON shape above (kept separate from the `@Model` types, which are
  persistence concerns, not wire-format concerns).
- `ContentImporter.importPackage(from: Data, into: ModelContext) throws -> ContentPackage`
  — decodes the JSON, builds the same `@Model` object graph
  `SampleContent` builds by hand (package → units → lessons → items →
  content, with inverses wired both directions), inserts it into the
  given context, and returns the created `ContentPackage`. Throws a
  descriptive error on a decode failure or an unrecognized
  `type`/`goal` string, rather than silently dropping the item.

This mirrors `SampleContent`'s existing construction pattern closely
enough that `ContentImporter`'s tests can assert the same kind of
invariants `ContentModelTests`/`SampleContentTests` already do (every
item has content, every item has a lesson, relationships wired both
ways) — just from JSON input instead of hardcoded Swift.

## Content generation process (this slice's actual authoring work)

Not code — a one-time (per batch) content-authoring pass:

1. Group the 120 words into 3-4 thematic units (Business & Economics,
   Science & Research Methods, Law & Policy/Society, Academic Writing
   & Communication are natural clusters for this particular word set)
   with lessons of ~10 words each.
2. For each word: write one clear, exam-register-appropriate English
   definition; 2-3 natural example sentences that actually demonstrate
   the word's real usage (not sentences that just restate the
   definition); an accurate, idiomatic Turkish translation (not a
   literal/machine-translation-style gloss); collocations that a
   learner would actually encounter (skip this field's *content*
   quality bar — not its presence, which is still required — for the
   rare word with no natural collocation, using the single headword's
   most common phrase pairing instead).
3. Assemble the per-word entries into the JSON document format above.
4. Validate: JSON decodes cleanly via `ContentImporter`'s test
   infrastructure, all 120 words present, no duplicate ids.

## What the app changes

`App/Sources/EnglishApp/AppModelContainer.swift`'s
`seedSampleContentIfNeeded` currently seeds `SampleContent
.ydsStarterPackage()`. This slice adds the generated JSON as a bundled
app resource and seeds from `ContentImporter.importPackage(from:
into:)` instead — `SampleContent` stops being used by the app (it
remains only as `LearningEngine`'s own test fixture). This is a
one-line swap in the seeding call, not a redesign of the seeding flow
itself.

## Testing

- `ContentImporterTests` (in `LearningEngine`, run via
  `scripts/ci-test.sh`): a small (~2-3 item) inline JSON fixture
  covering the full package→unit→lesson→item→content nesting, decode
  success, relationship wiring, and at least one deliberately malformed
  fixture (missing field / unrecognized enum string) asserting the
  import throws rather than silently producing partial data.
- The real 120-word generated JSON is validated by successfully
  importing without error and item-counting (120 items, correct unit/
  lesson counts) — not by hand-checking every definition in an
  automated test (content quality is a human/LLM authoring
  concern, not something a unit test can grade).

## Future work this unblocks

More AWL sublists or an NGSL-based general list for non-YDS packages,
each following the same JSON format and `ContentImporter` path with no
further engine changes.
